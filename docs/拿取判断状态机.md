## 拿取检出状态机与传递给 SAM3D Body 的数据规格

### 1. 追踪窗口

追踪以拍照时间为基准：

```text
tracking_start_frame = first Shigurei frame whose timestamp >= photo_timestamp
tracking_end_time = photo_timestamp + TAKEN_OBJECT_TRACKING_DURATION_SECONDS
```

默认追踪上限仍为 10 分钟。单独离线回放时使用
`TAKEN_OBJECT_OFFLINE_STOP_WHEN_HISTORY_EXHAUSTED=true`，读完现有 history 后直接结束，不再等待实时数据补齐整个 10 分钟窗口。

初始化失败条件：

```text
photo_timestamp 之后第一帧延迟 > TAKEN_OBJECT_INIT_MAX_START_DELAY_SECONDS
YOLO-first 初始化超过 TAKEN_OBJECT_YOLO_INIT_HARD_TIMEOUT_SECONDS
YOLO-first 和允许的 fallback 都无法建立可信 mask
```

---

### 2. 默认模式：YOLO-first

默认 `TAKEN_OBJECT_TRACKING_MODE=yolo_primary`。旧的 projected mesh mask 流程不再作为主流程，只在以下情况作为 fallback：

```text
TAKEN_OBJECT_ENABLE_LEGACY_FALLBACK=true
```

直接运行旧流程需要显式设置：

```text
TAKEN_OBJECT_TRACKING_MODE=legacy_projected_mask
TAKEN_OBJECT_ENABLE_LEGACY_PROJECTED_MASK=true
```

YOLO-first 的分工是：

```text
YOLO: 目标关联、粗筛发生变化的时间段
depth: 物理状态确认，区分遮挡/拿走
RGB: 在 depth 确认后回溯精确拿走帧
```

---

### 3. 模型中心投影与 YOLO 目标关联

初始化先从 task JSON 获取物体中心：

```text
ModelBounds.aabb_min_aruco + ModelBounds.aabb_max_aruco 的中心
否则 object_aruco.position
```

再使用 `data/aruco/shigure_marker_history/latest_marker_6d_pose.json` 中的
`opencv_camera_pose` 和当前 Shigure CameraInfo，将该中心投影到 Shigure RGB-D 图像，得到：

```text
projected_center_pixel
projected_center_depth_m
```

随后在唯一 YOLO payload 中寻找对应目标。匹配分数包含：

```text
YOLO bbox/mask 中心与 projected_center_pixel 的距离
projected_center_pixel 是否落在 mask/bbox 内
YOLO mask 内 median depth 与 projected_center_depth_m 的差异
```

拍摄时间之前最多使用 `TAKEN_OBJECT_YOLO_PRE_CAPTURE_UNIQUE_COUNT=3` 个唯一 YOLO 结果作为辅助证据。前向结果允许不连续，但只用于确认 id，不直接建立 reference depth。如果前向结果和拍摄后候选冲突，直接弃用前向证据。

---

### 4. YOLO 稳定初始化

正式初始化只使用拍摄时间之后的唯一 YOLO 结果。默认要求同一个 `object_id` 满足：

```text
TAKEN_OBJECT_YOLO_INIT_STABLE_UNIQUE_COUNT = 3
```

稳定窗口检查：

```text
中心移动 <= max(TAKEN_OBJECT_YOLO_STABLE_MAX_CENTER_PX, bbox_diag * TAKEN_OBJECT_YOLO_STABLE_MAX_CENTER_BBOX_RATIO)
mask IoU >= TAKEN_OBJECT_YOLO_STABLE_MIN_MASK_IOU
mask median depth 变化 <= TAKEN_OBJECT_YOLO_STABLE_MAX_DEPTH_DELTA_M
```

稳定开始第一帧的 YOLO mask 作为 `cached_trusted_mask`，该帧 mask 内有效 depth 作为 `cached_depth`。最小可信面积仍沿用旧状态机：

```text
TAKEN_OBJECT_TRUSTED_MASK_MIN_IMAGE_RATIO = 0.003
```

YOLO 初始化可向后等待 `TAKEN_OBJECT_YOLO_INIT_HARD_TIMEOUT_SECONDS`，默认 60 秒。失败后，如果 legacy fallback 开启，则重头进入旧 projected-mask 状态机；否则返回 `INIT_FAILED`。

---

### 5. YOLO 粗筛与 depth 细筛

初始化成功后，不对每个 RGB-D 帧都做完整判断。主循环先看唯一 YOLO：

```text
同 id 仍在原位置：继续等待
同 id 中心明显移动：从上一个 YOLO 时间点附近开始跑 depth 状态机细筛
id 短暂消失：使用 cached_trusted_mask 内 depth 判断遮挡/拿走/unknown
```

YOLO 移动防抖阈值：

```text
普通移动: max(TAKEN_OBJECT_YOLO_MOVE_CENTER_PX, bbox_diag * TAKEN_OBJECT_YOLO_MOVE_CENTER_BBOX_RATIO)
强移动: max(TAKEN_OBJECT_YOLO_MOVE_STRONG_CENTER_PX, bbox_diag * TAKEN_OBJECT_YOLO_MOVE_STRONG_BBOX_RATIO)
普通移动连续 TAKEN_OBJECT_YOLO_MOVE_STABLE_UNIQUE_COUNT 个唯一 YOLO 后触发
```

由于 YOLO 更新慢，YOLO 时间点只作为粗筛起点。真正的拿走时间由 depth 细筛和 RGB 回溯确定。

---

### 6. depth 遮挡/拿走判定

depth 判定沿用旧状态机的核心阈值。对 `cached_trusted_mask` 内有效 depth 计算：

```text
depth_delta[p] = current_depth[p] - cached_depth[p]
```

遮挡像素：

```text
depth_delta[p] <= TAKEN_OBJECT_OCCLUSION_DELTA_M
默认等价于当前 depth 更近 0.1m
```

拿走候选像素：

```text
depth_delta[p] >= TAKEN_OBJECT_TAKEN_DELTA_M
默认等价于当前 depth 更远 0.1m
```

完全遮挡：

```text
occluded_ratio >= TAKEN_OBJECT_FULL_OCCLUSION_RATIO
```

拿走确认：

```text
taken_ratio >= TAKEN_OBJECT_TAKEN_RATIO
连续 TAKEN_OBJECT_TAKEN_CONSECUTIVE_FRAMES 帧
```

id 消失时，如果 mask 范围内同时有一部分不变、一部分更近、几乎没有更远，则视作局部遮挡/unknown，不直接判拿走。对应阈值：

```text
TAKEN_OBJECT_PARTIAL_OCCLUSION_CLOSER_RATIO
TAKEN_OBJECT_PARTIAL_OCCLUSION_UNCHANGED_RATIO
TAKEN_OBJECT_PARTIAL_OCCLUSION_DEEPER_MAX_RATIO
```

---

### 7. RGB 回溯

depth 状态机确认拿走后，继续使用旧 RGB 回溯逻辑，在候选拿走时间前最多
`TAKEN_OBJECT_RGB_BACKTRACK_SECONDS` 内寻找稳定帧。输出仍为：

```text
TakenObjectDetection.result_timestamp
TakenObjectDetection.backup_shigurei_dir
```

备份目录仍包含：

```text
rgb.png
depth.png
camera_info.json
active_objects.json
marker_6d_pose.json
meta.json
```

---

### 8. history 读取性能约定

拿取检测先读取 chunk manifest 和去重 YOLO JSON，不解码视频。只有以下场景才解码 RGB-D chunk：

```text
YOLO 目标匹配需要 mask 内 median depth
YOLO 稳定初始化需要 reference depth
YOLO 粗筛命中后需要 depth 细筛
最终 RGB 回溯需要 RGB 帧
legacy fallback 需要完整 depth 状态机
```

`ShigureRgbdCache` 的 decoded chunk LRU 默认最多 5 个 chunk，decoded frames 只放内存不落盘。recorder 进程内还维护最近一个 chunk 长度的 raw RGB-D ring buffer，供同进程实时读取；跨进程读取仍以已 finalize 的 chunk 为准。
