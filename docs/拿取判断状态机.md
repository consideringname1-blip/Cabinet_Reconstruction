## 拿取检出状态机与传递给 SAM3D Body 的数据规格

### 1. 追踪起点与 worker 启动模式

追踪起始帧定义为：

```text
tracking_start_frame = first Shigurei frame whose timestamp >= photo_timestamp
```

追踪结束时间定义为：

```text
tracking_end_time = tracking_start_frame.timestamp + tracking_duration
```

其中 `tracking_duration` 由 `setting` 设定，默认 10 分钟。

worker 具有两种启动模式：

1. `offline+online`

   * 由前面代码调用启动。
   * 会跑完整个追踪时间窗口，即从 `tracking_start_frame` 到 `tracking_end_time`。

2. `pure_offline`

   * 单独启动时使用。
   * 不强制跑完整个 10 分钟。
   * 跑完现有缓存帧后结束。
   * 如果缓存结束时没有检测到拿走，则返回 `NOT_TAKEN`。

初始化失败条件：

```text
如果 photo_timestamp 之后的第一帧与 photo_timestamp 的时间差 > 1s，则返回 INIT_FAILED。
如果从 tracking_start_frame 开始 60s 内没有完成初始化，则返回 INIT_FAILED。
```

未检测到拿走的返回条件：

```text
如果初始化成功，但在当前模式允许的追踪范围内没有检测到拿走，则返回 NOT_TAKEN。
```

---

### 2. 前置投影 mask

首先将生成的 3D mesh 投影到 Shigurei 视角下，得到固定的 2D 投影 mask：

```text
projected_mesh_mask
```

该 mask 只用于初始化可信 mask。

可信 mask 初始化成功后，`projected_mesh_mask` 不再参与后续拿取判定。

---

### 3. 初始化可信 mask

从 `tracking_start_frame` 开始尝试初始化。

初始化稳定窗口长度由 `setting` 设定，默认：

```text
init_stable_duration = 3s
```

在初始化稳定判定中，先排除背景区域。背景区域定义为：

```text
depth > mesh_front_surface_max_depth + background_exclusion_tolerance
```

其中：

```text
background_exclusion_tolerance = 0.1m
```

`mesh_front_surface_max_depth` 指投影到 Shigurei 视角下的 3D mesh 前表面最远端深度。
这里的“前表面”是相对于 Shigurei 相机视角而言，被 z-buffer 可见的 mesh 前表面；再远的部分视为背面或被前表面挡住的部分。

无效深度不参与初始化稳定判定。
无效深度的判断不在状态机中额外定义，而由深度读取层或深度解码层提供有效深度 mask。状态机只接收并使用：

```text
valid_depth_mask
```

初始化稳定判定方式如下：

在 `projected_mesh_mask` 范围内，排除背景像素和无效深度像素后，得到：

```text
valid_init_mask
```

对 `valid_init_mask` 内每个像素，计算该像素在稳定窗口内的深度变化范围：

```text
depth_range[p] = max(depth[p] during init window) - min(depth[p] during init window)
```

如果满足：

```text
count(depth_range[p] <= init_stable_depth_delta) / count(valid_init_mask) >= init_stable_pixel_ratio
```

则认为该窗口深度稳定。

默认 setting：

```text
init_stable_depth_delta = 0.1m
init_stable_pixel_ratio = 0.95
init_stable_duration = 3s
```

稳定条件满足后，进一步筛选可信 mask。可信 mask 的深度范围要求为：

```text
mesh_front_surface_min_depth - trusted_depth_tolerance
<= mean_depth[p] <=
mesh_front_surface_max_depth + trusted_depth_tolerance
```

其中：

```text
trusted_depth_tolerance = 0.1m
```

`mean_depth[p]` 是初始化稳定窗口内该像素深度的平均值。

根据当前随附 mask 图像估计，正常可信 mask 约为 7059 像素，占 1280×720 全图约 0.766%。
因此初始化可信 mask 的最小面积比例设为：

```text
trusted_mask_min_image_ratio = 0.003
```

即可信 mask 像素数至少应达到全图像素数的 0.3%。
在 1280×720 图像下，对应约 2765 像素。

如果可信 mask 像素数不满足该比例，则初始化不成功，继续等待后续帧。

初始化成功后，缓存：

```text
cached_trusted_mask
cached_depth[p] = mean_depth[p] within init stable window
cached_init_rgb[p] = RGB value at initialization end frame within cached_trusted_mask
```

后续所有遮挡、拿走、RGB 回溯、JSON 坐标计算都基于该初始化可信 mask。

---

### 4. 后续每帧遮挡判定

初始化完成后，后续所有判定只基于 `cached_trusted_mask`。

每一帧先取得当前帧的：

```text
valid_depth_mask
```

无效深度像素不参与遮挡判定、拿走判定和比例统计。

在 `cached_trusted_mask` 内，排除当前帧无效深度像素后，比较当前深度与初始化缓存深度：

```text
depth_delta[p] = current_depth[p] - cached_depth[p]
```

遮挡像素定义为：

```text
depth_delta[p] <= -occlusion_depth_delta
```

默认：

```text
occlusion_depth_delta = 0.1m
```

遮挡比例定义为：

```text
occluded_ratio = occluded_pixel_count / valid_trusted_pixel_count
```

其中：

```text
valid_trusted_pixel_count = count(cached_trusted_mask ∩ valid_depth_mask)
```

根据当前 mask 实际大小，完全遮挡阈值默认设为：

```text
full_occlusion_ratio_threshold = 0.90
```

如果：

```text
occluded_ratio >= full_occlusion_ratio_threshold
```

则状态机进入完全遮挡处理流程。

未遮挡部分定义为：

```text
unoccluded_mask = cached_trusted_mask ∩ valid_depth_mask - occluded_mask
```

后续“未遮挡部分”统一指 `cached_trusted_mask` 内当前有效且未被遮挡的部分，与最初的 `projected_mesh_mask` 无关。

---

### 5. 非完全遮挡状态下的拿走判定

在非完全遮挡状态下，基于 `unoccluded_mask` 判断物体是否被拿走。

拿走候选像素定义为：

```text
depth_delta[p] >= taken_depth_delta
```

默认：

```text
taken_depth_delta = 0.1m
```

拿走候选比例定义为：

```text
taken_ratio = taken_candidate_pixel_count / unoccluded_pixel_count
```

如果：

```text
taken_ratio >= taken_ratio_threshold
```

则该帧判定为拿走候选帧。

默认：

```text
taken_ratio_threshold = 0.65
```

如果该条件连续满足 3 帧，则判定物体被拿走，并记录当前深度判定帧：

```text
depth_taken_frame
```

---

### 6. 完全遮挡状态下的拿走处理

假设初始化成功前，不会发生完全遮挡状态下拿走。

初始化成功后，如果进入完全遮挡状态，则记录第一次被判定为完全遮挡的帧：

```text
full_occlusion_start_frame
```

完全遮挡解除后，复用非完全遮挡状态下的拿走判定。

如果完全遮挡解除后满足拿走判定，则认为物体是在完全遮挡期间被拿走。

这种情况下，拿走时间近似返回为：

```text
full_occlusion_start_frame.timestamp
```

完全遮挡分支不进行 RGB 回溯，直接将结果写入 JSON，传递给后续 SAM3D Body。

---

### 7. RGB 回溯精细检测

RGB 回溯只用于非完全遮挡状态下的拿走检测。

由于基于深度的拿走判定可能滞后，因此在获得 `depth_taken_frame` 后，从该帧向前最多回溯一段时间：

```text
rgb_backtrack_duration = 5s
```

RGB 回溯目标是找到：

```text
拿走前的最后稳定帧
```

RGB 比较只在当前帧的未遮挡可信 mask 范围内进行，即：

```text
rgb_compare_mask = cached_trusted_mask ∩ valid_depth_mask - current_occluded_mask
```

RGB 稳定判定包含两个条件。

条件 1：相邻两帧 RGB 平均绝对差小于阈值：

```text
mean_absolute_rgb_difference(frame_t, frame_t_minus_1, rgb_compare_mask)
< rgb_adjacent_diff_threshold
```

条件 2：当前帧与初始化结束时缓存的 RGB 图像，在未遮挡可信 mask 范围内的平均绝对差小于阈值：

```text
mean_absolute_rgb_difference(frame_t, cached_init_rgb, rgb_compare_mask)
< rgb_init_diff_threshold
```

其中：

```text
rgb_adjacent_diff_threshold
rgb_init_diff_threshold
```

均由 `setting` 设定。

从 `depth_taken_frame` 向前搜索，找到距离 `depth_taken_frame` 最近、且满足上述 RGB 稳定条件的帧，作为：

```text
rgb_backtracked_frame
```

如果 5 秒回溯范围内找不到满足条件的帧，则使用：

```text
depth_taken_frame
```

作为最终结果帧。

非完全遮挡分支最终输出的结果时间戳为：

```text
rgb_backtracked_frame.timestamp
```

如果 RGB 回溯失败，则输出：

```text
depth_taken_frame.timestamp
```

---

### 输出运行模式

该 worker 具有两种输出运行模式：

1. `minimal_output`

   * 当前默认的最小运行模式。
   * 只输出后续 SAM3D Body 必须使用的数据。
   * 包括：

     * `result_timestamp`
     * 结果帧对应的 Shigurei 数据备份文件夹

2. `full_output`

   * 全量运行模式。
   * 在 `minimal_output` 的基础上，额外输出用于检查和调试的中间结果。
   * 全量输出不改变状态机判定逻辑，只增加文件保存。

输出模式由 `setting` 指定：

```text
output_mode = "minimal_output" or "full_output"
```

---

### 8. 写入 JSON、备份 Shigurei 数据并传递给 SAM3D Body

SAM3D Body 从 JSON 文件中读取拿取检出结果。

状态机在确定最终结果帧后，需要将该结果帧对应的 Shigurei 数据备份到 `output` 文件夹下的一个新的 Shigurei 子文件夹中。

该子文件夹名称由 Codex 在实现时拟定，但必须满足：

```text
1. 位于 output 文件夹下。
2. 是专门保存本次拿取检出结果帧数据的独立文件夹。
3. 后续 SAM3D Body 只从该备份文件夹中读取该帧数据。
```

最终结果帧来源如下：

1. 非完全遮挡分支中，如果 RGB 回溯成功：

```text
result_frame = rgb_backtracked_frame
result_timestamp = rgb_backtracked_frame.timestamp
```

2. 非完全遮挡分支中，如果 RGB 回溯失败：

```text
result_frame = depth_taken_frame
result_timestamp = depth_taken_frame.timestamp
```

3. 完全遮挡分支中，如果完全遮挡解除后复用拿走判定并确认物体已被拿走：

```text
result_frame = full_occlusion_start_frame
result_timestamp = full_occlusion_start_frame.timestamp
```

状态机需要将 `result_frame` 对应的三类 Shigurei 数据备份到该子文件夹中：

```text
1. RGB 图像
2. Depth 图像
3. CameraInfo / 相机参数
```

在 `minimal_output` 模式下，JSON 写入内容包括：

```text
result_timestamp
backup_shigurei_dir
```

其中：

```text
result_timestamp = 最终结果帧的时间戳
backup_shigurei_dir = output 文件夹下保存该结果帧 Shigurei 数据的备份子文件夹路径
```

JSON 中不写入图像比例坐标。
JSON 中不写入深度值。
JSON 中不写入 mask 信息。

后续 SAM3D Body 根据 JSON 中的 `backup_shigurei_dir` 读取备份后的 RGB 图像、Depth 图像和 CameraInfo / 相机参数，并以 `result_timestamp` 作为对应时间戳。

---

### 9. full_output 模式下的额外输出文件

当 `output_mode = "full_output"` 时，除 `minimal_output` 中的 JSON 和 Shigurei 数据备份外，还需要额外输出以下文件。

这些文件只用于调试、检查和可视化，不参与后续状态机判定。

#### 9.1 可信 mask

输出初始化完成后的可信 mask：

```text
cached_trusted_mask
```

该文件表示初始化成功后确定的可信 mask 区域。

#### 9.2 含有深度的可信 mask

输出初始化完成后的含深度可信 mask：

```text
cached_depth[p], p in cached_trusted_mask
```

该文件保存可信 mask 区域内每个像素在初始化稳定窗口内的平均深度。

可信 mask 外的区域不保存有效深度值，或者置为实现中约定的空值。

#### 9.3 含有 RGB 图的可信 mask

输出初始化完成时的 RGB 可信 mask：

```text
cached_init_rgb[p], p in cached_trusted_mask
```

该文件保存初始化结束帧中，可信 mask 区域内的 RGB 图像。

可信 mask 外的区域不保存有效 RGB 值，或者置为实现中约定的空值。

#### 9.4 深度拿取判断帧的判断依据可视化图

输出深度拿取判断帧对应的 mask 判断依据图。

该图用于显示在深度拿取判定帧上，各类 mask 的空间关系。

其中：

```text
原始 mask = projected_mesh_mask
可信 mask = cached_trusted_mask
遮挡部分 mask = depth_taken_decision_frame 上的 occluded_mask
拿走部分 mask = depth_taken_decision_frame 上的 taken_candidate_mask
```

颜色规定如下：

```text
黄色 = 原始 mask
绿色 = 可信 mask
蓝色 = 遮挡部分 mask
红色 = 拿走部分 mask
```

该可视化图以深度拿取判断帧的 RGB 图像作为底图。
mask 区域直接使用纯色覆盖，不进行透明叠加，不进行颜色混合。

覆盖顺序为：

```text
1. 原始 mask 覆盖为黄色
2. 可信 mask 覆盖为绿色
3. 遮挡部分 mask 覆盖为蓝色
4. 拿走部分 mask 覆盖为红色
```

后覆盖的 mask 优先级更高。

因此，如果同一像素同时属于多个 mask，则最终颜色由覆盖顺序中更靠后的 mask 决定。

`depth_taken_decision_frame` 定义为实际确认深度拿取判定成立的帧：

```text
非完全遮挡分支：
depth_taken_decision_frame = depth_taken_frame

完全遮挡分支：
depth_taken_decision_frame = 完全遮挡解除后，复用非完全遮挡拿走判定并确认物体已消失的那一帧
```

注意：
完全遮挡分支的最终 `result_timestamp` 仍然是 `full_occlusion_start_frame.timestamp`，但用于输出判断依据图的 `depth_taken_decision_frame` 是遮挡解除后确认物体消失的那一帧。

#### 9.5 full_output 模式下的额外调试 JSON

当 `output_mode = "full_output"` 时，除最小模式输出的主 JSON 外，还需要额外输出一个调试用 JSON 文件。

该 JSON 只用于检查、调试和复现实验，不作为后续 SAM3D Body 的必要输入。

调试 JSON 文件名由 Codex 在实现时拟定，建议命名为：

```text
debug_meta.json
```

该 JSON 至少包含以下内容。

---

##### 1. 运行基本信息

```text
output_mode
worker_start_mode
final_status
result_reason
```

其中：

```text
output_mode = minimal_output or full_output
worker_start_mode = offline+online or pure_offline
final_status = INIT_FAILED / NOT_TAKEN / TAKEN
result_reason = 触发最终结果的原因
```

`result_reason` 可取：

```text
depth_taken
rgb_backtracked
rgb_backtrack_failed_use_depth_taken_frame
full_occlusion_taken
init_failed_no_start_frame
init_failed_timeout
not_taken_timeout
not_taken_cache_end
```

---

##### 2. 时间戳信息

```text
photo_timestamp
tracking_start_timestamp
tracking_end_timestamp
init_start_timestamp
init_success_timestamp
depth_taken_timestamp
rgb_backtracked_timestamp
result_timestamp
full_occlusion_start_timestamp
full_occlusion_end_timestamp
```

如果某项没有发生，则写为 `null`。

其中：

```text
result_timestamp = 最终写入主 JSON 的时间戳
```

---

##### 3. setting 快照

保存本次运行实际使用的主要阈值：

```text
tracking_duration
init_timeout
init_stable_duration
init_stable_depth_delta
init_stable_pixel_ratio
background_exclusion_tolerance
trusted_depth_tolerance
trusted_mask_min_image_ratio
occlusion_depth_delta
taken_depth_delta
taken_ratio_threshold
taken_consecutive_frames
full_occlusion_ratio_threshold
rgb_backtrack_duration
rgb_adjacent_diff_threshold
rgb_init_diff_threshold
```

该部分用于防止之后只看到结果，但不知道当时使用了哪组参数。

---

##### 4. 初始化统计信息

```text
image_width
image_height
projected_mesh_mask_pixel_count
valid_init_pixel_count
trusted_mask_pixel_count
trusted_mask_image_ratio
init_stable_pixel_ratio_observed
init_depth_range_mean
init_depth_range_median
init_depth_range_max
```

其中：

```text
trusted_mask_image_ratio = trusted_mask_pixel_count / (image_width * image_height)
```

---

##### 5. 深度拿取判定统计信息

如果发生深度拿取判定，则保存：

```text
depth_taken_decision_timestamp
valid_trusted_pixel_count
occluded_pixel_count
occluded_ratio
unoccluded_pixel_count
taken_candidate_pixel_count
taken_ratio
```

如果没有发生深度拿取判定，则这些字段写为 `null`。

其中：

```text
depth_taken_decision_timestamp
```

定义为实际确认深度拿取判定成立的帧：

```text
非完全遮挡分支：
depth_taken_decision_timestamp = depth_taken_frame.timestamp

完全遮挡分支：
depth_taken_decision_timestamp = 遮挡解除后确认物体消失的那一帧时间戳
```

---

##### 6. RGB 回溯统计信息

如果执行了 RGB 回溯，则保存：

```text
rgb_backtrack_executed
rgb_backtrack_success
rgb_backtrack_start_timestamp
rgb_backtrack_end_timestamp
rgb_backtracked_timestamp
rgb_adjacent_diff_at_selected_frame
rgb_init_diff_at_selected_frame
```

如果没有执行 RGB 回溯，则：

```text
rgb_backtrack_executed = false
```

并且其他 RGB 回溯字段写为 `null`。

---

##### 7. 完全遮挡统计信息

如果进入过完全遮挡状态，则保存：

```text
full_occlusion_entered
full_occlusion_start_timestamp
full_occlusion_end_timestamp
full_occlusion_max_ratio
full_occlusion_taken_confirmed
```

如果没有进入完全遮挡状态，则：

```text
full_occlusion_entered = false
```

并且其他完全遮挡字段写为 `null`。

---

##### 8. 输出文件路径

保存 full_output 模式下额外输出文件的路径：

```text
backup_shigurei_dir
trusted_mask_path
trusted_depth_mask_path
trusted_rgb_mask_path
depth_taken_decision_visualization_path
```

这些路径指向实际保存的文件。
JSON 中不直接保存 mask、depth 或 RGB 的完整数组。
